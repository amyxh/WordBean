# 一、文档引言

## 1.1 设计目的

1.  明确“单词豆”V1.0版本的技术架构、模块划分、核心流程与接口规范，统一开发标准，降低跨端协作成本；

2.  聚焦“自定义单词管理+连连看核心游戏+本地数据存储”核心功能，规避技术风险，确保多端适配流畅、本地存储稳定、操作响应高效；

3.  预留后期扩展接口（如教材词汇库、账号同步），为V2.0及以后迭代奠定架构基础，避免重构核心代码。

## 1.2 设计范围

覆盖“单词豆”V1.0版本全量功能模块，包括：自定义单词管理模块、连连看核心游戏模块、基础进度跟踪模块、基础设置模块、多端适配模块，以及非功能需求（性能、安全、兼容性）对应的技术实现方案。

## 1.3 核心设计原则

1.  跨端统一：采用Uni-app框架实现“一次开发，多端部署”，确保手机/平板/电脑/小程序端界面与逻辑一致性；

2.  轻量化架构：规避复杂依赖，优先本地存储，减少云端交互，确保首屏加载≤3秒、游戏关卡加载≤1秒；

3.  模块解耦：核心模块（单词管理、游戏逻辑、数据存储）独立设计，通过接口通信，提升可维护性与扩展性；

4.  儿童友好：优化触控响应、降低操作延迟，适配儿童操作习惯，避免卡顿、闪退等影响体验的问题；

5.  安全合规+0成本适配：本地数据加密存储，无云端上传，仅申请必要权限；采用免费技术栈与工具，规避付费服务，实现0成本开发落地，符合《未成年人网络保护条例》与《数据安全法》。

# 二、总体架构设计

## 2.1 架构分层设计（四层架构）

采用“UI层→业务逻辑层→数据访问层→基础支撑层”四层架构，各层独立解耦，通过接口交互，便于开发维护与后期扩展。

|架构分层|核心职责|技术实现|对应模块|
|---|---|---|---|
|UI层（视图层）|负责多端界面渲染、用户操作交互、视觉反馈展示（动画/音效），适配不同终端分辨率与操作逻辑|Uni-app（Vue3语法）、uView UI组件库、自定义卡通组件、音效/动画素材集成|所有模块的界面展示（单词录入界面、游戏界面、进度跟踪界面等）|
|业务逻辑层（核心层）|实现核心业务逻辑，包括单词管理、游戏匹配、进度统计、设置管控等，处理UI层交互请求|Vue3 Composition API、模块化函数设计、事件总线（跨组件通信）|自定义单词管理、连连看核心游戏、基础进度跟踪、基础设置|
|数据访问层（数据层）|负责本地数据的存储、读取、更新、删除，以及数据导出/备份，实现数据加密与安全管控|Uni-app Storage（本地存储）、SQLite（本地数据库）、数据加密算法（AES-128）|数据存储与同步、数据备份与清除|
|基础支撑层（支撑层）|提供通用工具、多端适配、权限管理、日志记录等基础支撑，保障整体架构稳定运行|Uni-app 多端适配API、通用工具类（格式校验、日期处理）、权限申请API、日志工具|多端适配、安全管控、权限管控、日志记录|
## 2.2 技术栈选型（轻量化、高适配）

### 2.2.1 前端核心技术

1. 框架：Uni-app（Vue3 + Vite）—— 跨端开发首选，支持多端统一部署，减少重复开发；

2. UI组件库：uView UI（Vue3版）—— 轻量、高效，适配多端，可自定义主题风格；

3. 本地存储：Uni-app Storage（简易数据）、SQLite（结构化数据，如单词集、学习记录）；

4. 动画/音效：Lottie（轻量动画）、uni.createInnerAudioContext（音效播放）；

5. 工具类：Day.js（免费日期处理）、原生JS表单校验（替代Validator付费工具）、js-base64（免费数据加密辅助）。

### 2.2.2 后端技术（极简设计，仅支撑本地数据交互）

V1.0版本无独立后端服务（规避云端依赖，实现轻量化），仅集成本地数据库与文件处理逻辑，后期V2.0新增账号同步、教材词汇库时，可扩展为“本地+云端”混合架构，后端技术选型如下：

1. 框架：Spring Boot（轻量微服务框架）；

2. 数据库：MySQL（云端数据存储）、Redis（缓存）；

3. 接口：RESTful API（供前端调用）；

4. 部署：后期扩展优先选用免费云服务（如阿里云免费版、腾讯云开发者版），Docker容器化部署（免费工具），支持弹性扩展。

### 2.2.3 开发/测试工具

1. 开发工具：HBuilder X（Uni-app专属开发工具）、VS Code（辅助开发）；

2. 测试工具：Uni-app 模拟器（多端模拟）、Chrome DevTools（调试）、Postman（后期接口测试）；

3. 版本控制：Git（代码管理）、GitLab/GitHub（仓库托管）；

4. 设计工具：Figma免费版（UI设计稿导入）、Draw.io（免费架构图绘制）、Canva免费版（简易素材制作）。

## 2.3 多端适配架构设计

基于Uni-app的多端编译能力，采用“统一代码+差异化适配”策略，确保各终端界面与功能一致性，同时适配不同终端操作习惯。

1. **统一代码层**：核心业务逻辑、UI组件、数据处理代码统一编写，避免重复开发；

2. **差异化适配层**：通过Uni-app条件编译（#ifdef ... #endif），针对不同终端做个性化适配：
        

    - 手机端：优化触控按钮尺寸（≥44px×44px）、竖屏布局、手势操作；

    - 平板端：支持横屏布局、双指缩放、界面元素自适应拉伸；

    - 电脑端：支持鼠标点击、键盘快捷键（如Enter匹配、Space提示）、分辨率自适应；

    - 小程序端：优化包体积（≤2MB）、首屏加载速度（≤2秒）、微信分享功能适配。

3. **资源适配**：图片资源采用自适应格式（svg/png），音效资源统一压缩（单文件≤50KB），避免终端适配卡顿。

# 三、核心模块详细设计

## 3.1 模块划分总览

V1.0版本划分为5个核心模块，各模块独立封装，通过接口交互，模块间依赖关系清晰，确保开发高效推进。

模块依赖关系：UI层 → 业务逻辑层（各核心模块） → 数据访问层 → 基础支撑层；各核心模块间无直接依赖，通过事件总线或全局状态通信。

## 3.2 自定义单词管理模块（P0级，核心重点）

### 3.2.1 模块功能定位

实现单词单条录入、文本批量导入、单词集创建/编辑/删除、单词集分享等功能，是“单词豆”V1.0的核心模块，支撑游戏内容定制。

### 3.2.2 核心子模块与流程

1. **单词录入子模块**核心功能：单条录入、文本批量导入、表单校验；流程设计：① 用户触发录入操作（单条/批量）→ ② 表单校验（单词非空、格式合规）→ ③ 数据处理（补充默认发音、生成唯一ID）→ ④ 调用数据访问层存储至本地数据库 → ⑤ 反馈录入结果（成功/失败提示）；关键设计：文本批量导入支持.txt格式解析，按“单词,音标,释义”格式拆分，错误数据单独提示，导入后支持编辑修正。

2. **单词集管理子模块**核心功能：单词集创建、列表展示、排序、编辑/删除、分享；流程设计：① 创建单词集（输入名称、选择分类）→ ② 关联单词数据 → ③ 列表展示（按创建时间/单词数排序）→ ④ 编辑/删除（弹窗确认，支持10秒撤销）→ ⑤ 分享（生成二维码/链接，支持微信分享）；关键设计：单词集ID采用“时间戳+随机数”生成，确保唯一性；内置单词集（动物/水果/颜色）默认存储在本地，支持编辑修改。

### 3.2.3 数据结构设计

|---|---|---|---|---|
|单词（word）|wordId|String|是|唯一标识，格式：timeStamp+random(6)|

||createTime|String|是|创建时间（格式：YYYY-MM-DD HH:MM:SS）|

## 3.3 连连看核心游戏模块（P0级，核心功能）

### 3.3.1 模块功能定位

实现单词集选择、关卡生成、核心匹配玩法、提示功能、互动反馈与奖励发放，是用户核心使用场景的载体，需保证操作流畅、反馈及时。

### 3.3.2 核心子模块与流程

1. **关卡生成子模块**核心功能：单词集选择、关卡参数生成、卡片数据组装；流程设计：① 用户选择单词集 → ② 系统获取单词集内单词数据 → ③ 根据单词数量生成关卡（10-20个/关）→ ④ 组装卡片数据（单词卡+释义卡/图片卡）→ ⑤ 随机排列卡片布局 → ⑥ 渲染关卡界面；关键设计：卡片ID唯一，布局按难度适配（简单3×4、中等4×5、困难5×6），确保同一关卡无重复卡片。

2. **匹配玩法子模块**核心功能：卡片点击、匹配校验、消除逻辑、提示功能；流程设计：① 用户点击第一张卡片（选中状态）→ ② 点击第二张卡片 → ③ 系统校验匹配关系（单词-释义/图片）→ ④ 匹配正确：消除卡片+播放音效/动画 → ⑤ 匹配错误：弹窗提示+取消选中 → ⑥ 触发提示功能：高亮可匹配卡片；关键设计：点击响应延迟≤0.3秒，消除动画时长≤0.5秒，提示功能每局限3次，避免过度依赖。

3. **反馈与奖励子模块**核心功能：即时交互反馈、勋章奖励发放、游戏结束统计；流程设计：① 连续匹配正确3次：弹出鼓励文字 → ② 完成一局游戏：发放1枚勋章 → ③ 累计5枚勋章：解锁简易道具 → ④ 游戏结束：统计时长、正确率、错误单词 → ⑤ 展示结束页面（支持重新挑战/退出）；关键设计：勋章数据本地存储，与用户设备绑定；结束页面数据实时统计，支持截图保存。

### 3.3.3 核心算法设计

1. **卡片匹配算法**：采用原生JS“键值对匹配”逻辑，无需引入第三方算法库，将单词作为key，释义/图片路径作为value，存储在对象中，点击卡片时通过key-value校验匹配关系，时间复杂度O(1)，确保匹配高效且无额外成本；

2. **卡片随机排列算法**：基于原生JS实现“Fisher-Yates 洗牌算法”，无需依赖第三方工具，对卡片数组进行随机打乱，确保每次关卡卡片排列顺序不同，避免用户记忆卡片位置；

3. **提示算法**：遍历所有未消除卡片，查找第一对可匹配卡片，通过样式修改实现高亮，避免提示过于频繁，影响学习效果。

## 3.4 基础进度跟踪模块（P0级）

### 3.4.1 模块功能定位

实现学习记录统计、学习日报生成、单词掌握率计算、历史记录管理，帮助家长跟踪孩子学习进度与效果。

### 3.4.2 核心子模块与流程

1. **学习记录统计子模块**核心功能：实时记录游戏数据、计算单词掌握率；流程设计：① 游戏结束：记录单词集ID、时长、正确率、错误单词ID → ② 累加单词匹配次数 → ③ 校验掌握条件（正确匹配≥3次）→ ④ 更新单词掌握状态 → ⑤ 计算单词集掌握率（已掌握单词数/总单词数）；关键设计：学习记录按日期分组存储，支持按日期筛选；掌握率实时更新，同步展示在单词集列表。

2. **学习日报子模块**核心功能：每日自动生成学习日报、支持查看/截图；流程设计：① 每日24:00触发日报生成 → ② 统计当日学习数据（时长、局数、正确率、错误单词）→ ③ 组装日报内容（文本+数据）→ ④ 存储至本地 → ⑤ 支持用户查看/截图保存；关键设计：日报生成时间≤10秒，数据准确；支持保存近7天日报，过期自动清理（可手动备份）。

3. **历史记录管理子模块（P1级）**核心功能：历史记录存储、筛选、删除；流程设计：① 保存近7天学习记录 → ② 支持按日期筛选记录 → ③ 允许删除无用记录 → ④ 清除记录前弹窗确认；关键设计：删除操作响应≤0.5秒，记录删除后不可恢复（除10秒内撤销），确保数据安全。

## 3.5 基础设置模块（P0级）

### 3.5.1 模块功能定位

实现数据存储与同步、安全管控、音效/动画设置、数据备份与清除，保障产品使用安全、操作便捷，适配不同使用场景。

### 3.5.2 核心子模块与流程

1. **数据存储与同步子模块**核心功能：本地数据存储、手动数据导出；流程设计：① 核心数据（单词集、学习记录等）加密后存储至本地数据库 → ② 用户触发导出操作 → ③ 打包数据为文本文件/截图 → ④ 保存至本地设备 → ⑤ 提示导出成功；关键设计：采用AES-128加密算法对本地数据加密，防止数据泄露；暂不支持自动多端同步，V2.0可扩展账号关联同步。

2. **安全管控子模块**核心功能：每日学习时长限制、超时锁定、权限管控；流程设计：① 用户设置每日学习时长上限（默认15分钟）→ ② 累计学习时长达到上限 → ③ 自动锁定游戏界面 → ④ 当日24:00解锁 → ⑤ 权限申请：仅申请拍照/相册权限（用于配图上传）；关键设计：时长统计实时准确，锁定后无法绕过，确保儿童合理使用。

3. **数据备份与清除子模块（P1级）**核心功能：手动数据备份、历史记录清除；流程设计：① 备份：用户触发备份 → ② 复制核心数据至本地备份目录 → ③ 提示备份成功；① 清除：用户触发清除 → ② 弹窗确认 → ③ 删除指定数据（历史记录/全部数据）→ ④ 提示清除成功；关键设计：备份数据单独存储，清除操作不影响备份数据；支持选择性清除（仅清除历史记录）。

# 四、接口设计

## 4.1 接口设计原则

1.  统一命名规范：采用“模块名_子模块名_功能描述”格式，如“wordInput_singleAdd”（单词录入_单条添加）；

2.  参数清晰：明确输入参数、输出参数的类型、必填项，添加备注说明；

3.  异常处理：接口返回统一格式（成功/失败标识、数据、提示信息），便于前端处理异常场景；

4.  低耦合：接口独立设计，模块间通过接口交互，避免直接依赖。

## 4.2 核心接口示例（按模块划分）

### 4.2.1 自定义单词管理模块接口
