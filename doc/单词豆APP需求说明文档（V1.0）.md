# 单词豆（儿童英语单词连连看小游戏）需求说明文档（V1.0）

文档版本：V1.0

编写日期：2025年12月30日

编写人：项目经理

适用范围：开发团队（前端/后端/测试）、设计团队、产品团队，作为V1.0版本开发落地、需求评审、测试验收的核心依据

# 一、项目基础信息

## 1.1 项目名称

正式名称：**单词豆**

定位：儿童英语单词记忆轻量化游戏工具（以连连看为载体，聚焦自定义单词录入核心功能）

## 1.2 项目核心目标

1.  产品目标：打造“轻量化+高适配+自定义”儿童英语单词记忆工具，解决孩子单词记忆枯燥、家长无法精准管控学习内容的痛点，第一版聚焦“自定义单词录入”核心功能，快速上线验证市场需求；

2.  用户目标：满足3-12岁儿童碎片化单词学习需求，让家长可按需定制学习内容（年级/教材/自定义词汇），提升孩子单词记忆效率与学习兴趣；

3.  落地目标：10-12周内完成V1.0版本开发上线，支持多端适配（手机/平板/电脑/微信小程序），核心功能无BUG，操作流程简洁易上手，7日用户留存率达30%以上（参考指标，可按灰度测试结果调整）。

## 1.3 核心设计原则

1.  多端适配优先：确保各终端界面适配流畅，操作逻辑一致，无适配卡顿、界面错乱问题；

2.  操作极简：核心操作流程≤2步，儿童可独立完成，家长定制单词内容操作便捷，无需复杂引导；

3.  自定义核心：第一版重点落地自定义单词录入功能，支持文本批量导入、单条添加，满足家长个性化需求；

4.  教育性与趣味性平衡：以单词记忆为核心，搭配轻量化游戏互动与反馈，避免纯娱乐化；

5.  合规安全：无广告植入，保护用户隐私（尤其是儿童信息），内容审核机制完善，符合《未成年人网络保护条例》；V1.0无付费功能，后续可评估新增付费模块（V2.0规划）。

# 二、用户与场景需求

## 2.1 目标用户画像

### 2.1.1 核心使用用户：3-12岁儿童（学龄前-小学六年级）

1.  认知特征：注意力集中时间10-15分钟，偏好具象化、色彩明快的内容，抵触复杂操作与机械背诵；

2.  行为特征：喜欢即时反馈与奖励，愿意为解锁道具/关卡持续参与，可独立完成简单点击/滑动操作；

3.  学习需求：需通过趣味方式巩固单词，适配自身年龄/年级的词汇难度，避免难度过高产生挫败感。

### 2.1.2 决策/操作用户：28-45岁家长（中产及以上家庭）

1.  核心诉求：可自定义孩子学习的单词内容（贴合教材/年级/个性化需求），跟踪学习进度，无广告干扰；

2.  行为特征：愿意花5分钟内完成单词定制，优先选择轻量化、易上手的产品，关注孩子学习效果与使用安全；

3.  潜在需求：后期可对接教材词汇库，支持Excel批量导入单词，生成详细学习数据报告。

## 2.2 核心使用场景

1. **场景一：课后单词复习（核心场景）**用户：小学1-6年级学生+家长；场景：孩子课后需复习当天所学单词，家长通过App/小程序录入对应教材单词（如人教PEP三年级上册单词），孩子进入连连看游戏匹配单词与释义，完成复习任务；需求要点：支持单条/文本批量录入单词，可添加单词释义、发音、配图，游戏难度适配单词数量与难度。

2. **场景二：碎片化学习（高频场景）**用户：3-6岁学龄前儿童+家长；场景：通勤、等待间隙，家长提前录入简单单词（如水果、动物类），孩子通过手机/小程序玩连连看，利用碎片化时间启蒙英语；需求要点：轻量化启动，操作简单，游戏时长可设置（如5分钟/局），避免过度使用。

3. **场景三：个性化单词积累（补充场景）**用户：小学高年级学生+家长；场景：孩子需积累课外拓展单词（如小升初核心词汇），家长通过文本文件批量导入对应单词列表，孩子通过游戏强化记忆，家长查看学习正确率与进度；需求要点：支持文本批量导入单词，可编辑/删除已录入单词，生成简易学习进度报告（Excel批量导入延后至V2.0）。

# 三、核心功能需求（V1.0版：自定义单词录入为核心）

## 3.1 功能模块总览

V1.0版本聚焦“自定义单词管理+连连看核心游戏+基础进度跟踪”三大核心模块，预留教材词汇库、AI发音校验等扩展接口，确保后期迭代无需大幅重构。

## 3.2 自定义单词管理模块（核心重点）

### 3.2.1 单词录入功能

1. **单条录入**：支持家长录入单词文本（必填）、音标（可选）、中文释义（必填）、英文发音（可选，默认系统合成发音）、自定义配图（可选，支持拍照/相册上传）；表单校验（如单词非空），录入成功弹窗提示，流程≤2步；

2. **批量录入**：V1.0优先支持文本文件（.txt）批量导入，导入模板含“单词、音标、释义”核心字段；支持导入预览、错误提示（如格式不符），导入后可编辑单个单词信息；单次导入上限50个单词，Excel批量导入延后至V2.0开发；

3. **单词分类**：支持按“年级/教材/主题”创建单词集（如“三年级上册-人教PEP”“水果类单词”），单个单词集可容纳10-50个单词（严格限制上限50个），便于孩子分批次学习；

4. **编辑与删除**：支持修改单词信息（文本/音标/释义等），删除单条单词或整个单词集；删除前弹窗确认，支持10秒内误删撤销，避免误操作。

### 3.2.2 单词集管理

1. **单词集列表**：展示所有创建的单词集，显示单词集名称、单词数量、创建时间，支持按创建时间/单词数量排序；列表加载流畅，排序功能无异常；

2. **单词集分享**：（P1优化任务）支持将单词集分享至微信好友/群，生成分享链接/二维码，好友可直接导入使用（如家长间分享教材单词集）；

3. **默认单词集**：系统内置3个基础单词集（启蒙级-动物/水果/颜色，各含20个核心单词），含单词、音标、释义、默认配图，供用户直接使用，支持编辑修改。

## 3.3 连连看核心游戏模块

### 3.3.1 游戏基础设置

1. **单词集选择**：进入游戏前，用户可选择已创建/内置的单词集，系统根据单词数量生成对应关卡（10-20个单词对应1关，50个单词对应3关）；选择后关卡生成时间≤1秒；

2. **匹配模式选择**：支持两种匹配模式（默认“单词-释义”，可选“单词-图片”），家长可在设置中默认模式；“单词-图片”模式仅支持家长自定义上传的配图，系统图库延后至V2.0新增；

3. **游戏时长设置**：支持设置单局游戏时长（5/10/15分钟，默认10分钟），超时未完成自动结束游戏，显示学习结果；

4. **难度设置**：支持选择难度（简单/中等/困难），对应不同的卡片布局与匹配时间限制（简单：3×4布局，无时间限制；中等：4×5布局，10分钟/局；困难：5×6布局，5分钟/局）。

### 3.3.2 游戏核心玩法

1. **卡片布局**：单词与对应释义/图片分别生成卡片，随机排列在游戏界面；卡片样式为卡通化设计，色彩明快，字体清晰（适配儿童阅读）；

2. **操作逻辑**：点击选中一张卡片，再点击对应匹配卡片，匹配正确则两张卡片消除，触发动画+音效反馈；匹配错误则弹窗提示“再试试吧”，无惩罚机制；操作响应无延迟；

3. **提示功能**：每局可使用3次提示功能，点击“提示”按钮，系统高亮一对可匹配卡片，避免孩子因卡关产生挫败感；

4. **游戏结束**：所有卡片消除则游戏胜利，显示“恭喜完成！”动画，展示本次游戏时长、正确率、错误单词列表；未完成则显示“继续加油！”，可选择重新挑战或退出；结束页面数据准确，操作无卡顿。

### 3.3.3 互动反馈与奖励

1. **即时反馈**：匹配正确播放欢快音效+卡片消除动画；连续匹配正确3次，弹出“真棒！”“太厉害啦”等鼓励文字；

2. **基础奖励**：完成一局游戏可获得1枚“单词豆”勋章，累计5枚勋章可解锁一个简易卡通道具（如IP头像框），提升孩子参与积极性；奖励实时到账，无异常弹窗；

3. **学习记录**：自动记录每局游戏的单词集、时长、正确率、错误单词，生成当日学习记录，供家长查看。

## 3.4 基础进度跟踪与设置模块

### 3.4.1 进度跟踪

1. **学习日报**：每日自动生成学习日报，包含当日学习时长、完成局数、平均正确率、重点错误单词，家长可查看/截图保存；日报生成时间≤10秒，数据准确；

2. **单词掌握率**：按单词集统计单词掌握率（正确匹配次数≥3次标记为“已掌握”），显示“已掌握/总单词”数量，便于家长针对性安排复习；掌握率实时更新，统计逻辑无误；

3. **历史记录**：（P1优化任务）保存近7天学习记录，支持按日期筛选、删除无用记录；筛选/删除操作响应≤0.5秒，记录无残留。

### 3.4.2 基础设置

1. **数据存储与同步**：默认本地存储单词集、学习记录（无需登录）；支持手动导出数据（如单词集文本文件、学习记录截图），便于多端迁移；暂不支持自动多端同步（避免登录依赖，V2.0可新增账号关联同步功能）；数据存储安全，本地文件加密，无云端上传风险。

2. **安全管控**：支持设置每日学习时长上限（10-30分钟，默认15分钟），超时自动锁定游戏；无广告植入，关闭弹窗权限，避免孩子误触；

3. **音效与动画设置**：支持开启/关闭游戏音效、动画，适配不同使用场景（如静音环境可关闭音效）；

4. **数据备份与清除**：（P1优化任务）支持手动备份单词集、学习记录（仅备份至本地，无云端备份），可一键清除历史学习记录，保护用户隐私；备份/清除操作无报错，数据安全无丢失。

## 3.5 预留扩展功能（V2.0及以后迭代规划）

1. 教材词汇库接口（V2.0优先）：对接主流教材（人教PEP、外研版等）词汇库，按年级/册数分类词汇，支持直接选择使用；

2. Excel批量导入（V2.0）：支持Excel格式导入单词，完善字段（含发音路径、配图路径批量导入），提供导入模板下载、批量编辑功能；

3. AI发音校验接口（V2.0延后）：支持语音录入与打分，新增单词跟读、发音打分功能，给出发音优化建议；

4. 亲子互动接口（V3.0）：新增亲子双人游戏模式，支持家长与孩子组队匹配，分工完成任务，共同获得奖励；

5. 数据报表接口（V2.0）：生成周/月学习报告，支持数据导出；新增薄弱单词分析、学习趋势图表；

6. 付费功能（V2.0评估后）：规划高级单词集、专属道具等付费模块，对接支付接口，完善付费合规流程。

# 四、交互与UI设计需求

## 4.1 交互设计核心要求

1. **操作极简**：核心流程操作步骤≤2步，如“选择单词集-开始游戏”“录入单词-保存”，避免冗余步骤；

2. **反馈及时**：所有操作（点击、录入、匹配）均有明确反馈（音效、动画、文字提示），响应时间≤0.5秒，无延迟；

3. **容错性强**：单词录入支持自动纠错（如拼写错误提示），游戏匹配错误无惩罚，支持重新匹配；误操作可撤销（如删除单词集可10秒内撤销）；

4. **儿童友好**：界面元素尺寸适配儿童操作，按钮、卡片间距合理，避免误触；提示文字简洁易懂（如“请选择要复习的单词集”），搭配卡通图标辅助理解。

## 4.2 UI设计核心要求

1. **风格定位**：卡通化、轻量化，色彩明快柔和（以蓝、黄、绿为主色调，避免刺眼颜色），适配儿童审美；打造专属IP“单词豆”（卡通豆子形象），贯穿整个界面，增强品牌辨识度；

2. **界面布局**：各终端界面布局统一，核心元素（单词集列表、游戏按钮、设置入口）位置固定，便于用户形成使用习惯；留白充足，避免元素过于拥挤；

3. **卡片与字体**：单词卡片采用圆角设计（圆角半径8px），边框柔和；字体选用清晰易读的卡通字体，单词字体大小≥16px（手机端），适配儿童阅读；

4. **动画与音效**：动画轻量化（时长≤1秒），避免过度复杂；音效欢快柔和，无刺耳声音；奖励动画简洁有趣（如勋章弹出、IP欢呼动画），提升用户愉悦感。

# 五、非功能需求

## 5.1 性能需求

1. 加载速度：App/小程序首屏加载≤3秒，游戏关卡加载≤1秒，单词集切换无延迟；

2. 稳定性：连续运行1小时无闪退、卡顿，单词录入与游戏操作响应流畅，本地数据存储无丢失；

3. 兼容性：各终端适配无BUG，不同系统/浏览器运行正常，无界面错乱、功能失效问题。

## 5.2 安全需求

1. 数据安全：单词集、学习记录等数据均采用本地加密存储，无云端上传操作，避免数据泄露风险；

2. 隐私保护：不收集用户任何个人信息（无需注册登录，无账号关联），所有数据默认本地存储，导出数据由用户自行保管；符合《未成年人网络保护条例》，用户可随时清除本地数据；

3. 权限管控：仅申请必要权限（如拍照、相册、麦克风，后期迭代使用），无过度授权，权限申请时明确告知用户用途。

## 5.3 可扩展性需求

1. 架构可扩展：核心模块解耦，新增功能（如教材词汇库、AI发音）无需重构原有代码，可直接接入预留接口；

2. 功能可扩展：支持后期新增关卡玩法、奖励机制、社交互动等功能，扩展成本低；

3. 词汇可扩展：支持后期接入海量词汇库，单词集容量可提升至100个单词/集，满足用户拓展需求。

# 六、项目开发与上线规划

## 6.1 开发周期规划（总周期：10-12周）

1. 第1-2周：需求评审与技术设计

## 8.1 单词批量导入模板示例（文本文件.txt）

格式要求：每行1个单词，字段用英文逗号分隔（顺序：单词,音标,中文释义），音标可选可留空；

## 8.2 核心术语定义

1. 单词集：包含多个单词的集合，可按年级/教材/主题分类，供用户选择游戏内容；

2. 连连看匹配模式：分为“单词-释义”“单词-图片”两种，用户可按需选择；

3. 单词掌握率：单单词正确匹配次数≥3次标记为“已掌握”，已掌握单词数/总单词数即为掌握率；

4. 多端同步（V1.0暂不支持）：V1.0默认本地存储，支持手动导出数据；V2.0可新增账号关联，实现同一账号多端同步（同步延迟≤3分钟）。
